# Android startup regression

This instrumentation APK runs against the installed release APK and its real WebView. It checks startup, the JavaScript bridge, all five navigation tabs, English settings, Shop, offline quest creation and persistence after a cold process restart. It only accepts an emulator and writes a test quest there.

Run `run.ps1` with absolute paths for `-Apk`, `-Adb`, `-AndroidJar`, `-BuildTools` and `-SigningKey`. The test and application must use the same signing key. `-Serial` defaults to `emulator-5556`, and `-ServerPort` to `5039`.

The two raw instrumentation reports are saved in `build/result.txt` and `build/restart-result.txt`. Success requires both `PASS:` and `INSTRUMENTATION_CODE: -1`.

The previous failure came from backslashes in the raw ZIP entry names generated by Windows aapt2. Windows ZIP APIs can normalize these names when reading them and conceal the problem. The production build now normalizes names before alignment and signing, and validates the final APK names. Runtime loading uses the original HTML/CSS/JS assets, with no generated Java page or inline script hash.
